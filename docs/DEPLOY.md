# Running Roomtone with Docker and Render

Roomtone runs as **one container**: FrankenPHP (PHP with Caddy built in) serves the site on `$PORT` (80 by default) and passes websockets on `/app/…` to Reverb, while the queue worker, Reverb and the scheduler run beside it (`docker/start.sh`, which restarts any of them that stops). SQLite lives in `/var/roomtone`. The container speaks plain HTTP; HTTPS comes from whatever is in front (Render, Cloudflare).

It is one container because SQLite sits on one disk, and on Render a disk belongs to a single service.

## Locally

```bash
docker compose up -d --build
docker compose exec app php artisan db:seed --class=DemoPartySeeder --force   # a fake demo party, no API calls
```

It reads the same `.env` as `composer run dev` (see the README); `compose.yaml` overrides what differs inside Docker (the URL, database path, Reverb address, logs and SSR). The `.env` file never goes into the image. Open http://localhost. `docker compose logs -f`, `docker compose exec app sh`, `docker compose down` (keeps the data; add `-v` to delete it).

Plain `composer run dev` (no Docker) is still the everyday setup.

### Make targets

`make` lists them. `make rebuild` is the everyday full refresh without Docker: clears the config, route, view and event caches, the compiled files and the front end's build output, reinstalls PHP and JS dependencies as locked, rebuilds the front end (client and SSR), and migrates. `make deploy` runs the tests, then `make rebuild`, then builds the Docker image from scratch (`--no-cache`) and recreates the container, waiting until `/up` answers (`SKIP_TESTS=1 make deploy` skips the tests). The application cache is left alone on purpose: it holds every Qloo answer (they cost quota) and the YouTube quota flag; `make clear-app-cache` wipes it. Render still deploys on every push, not through `make`.

## On Render

`render.yaml` is a Blueprint for one Docker web service with a 1 GB disk at `/var/roomtone`.

1. In Render: **New → Blueprint**, pick this repository. Render reads `render.yaml`.
2. Fill in the values it asks for: `APP_KEY` (`php artisan key:generate --show`), `APP_URL` (the public address, e.g. `https://roomtone.stackyard.io`), `QLOO_API_KEY`, `YOUTUBE_API_KEY`, `AI_PROVIDER_KEY`.
3. After the first deploy, build the demo party from live calls (Shell tab in Render):

   ```bash
   php artisan roomtone:demo:build
   ```

   It writes into the server's database only (never into the repository: Qloo's terms) and keeps the existing demo if anything falls short, so it is safe to re-run. It needs about 20 of the 100 daily YouTube searches. Until then `/e/DEMO` is a 404.

Every push to the branch redeploys. With a disk, Render stops the old container before starting the new one, so a deploy means a few seconds of downtime. Migrations run when the container starts (Render's pre-deploy command can't see the disk).

### Custom domain through Cloudflare

Add `roomtone.stackyard.io` as a custom domain on the Render service, then in Cloudflare a **CNAME** `roomtone` → the service's `onrender.com` address, with SSL/TLS mode **Full (strict)** (Render has a real certificate). `TRUSTED_PROXIES=*` lets Laravel read the visitor's IP and scheme through the proxies (the rate limits on setup, joins and requests depend on it). Websockets pass through both.

### Data

- Render snapshots the disk daily, but don't restore a snapshot of a live SQLite file. Use the app's own backups: `roomtone:backup` runs nightly at 03:30 and keeps the newest 7 `VACUUM INTO` copies in `/var/roomtone/backups/`.
- The Reverb app key is public (it is in the JavaScript); the secret is generated by Render.

## The smoke test

```bash
docker/smoke.sh
```

Builds the image and runs it the way Render does (`PORT=10000`, the `render.yaml` settings, a volume as the disk), then checks: the queue worker, Reverb and scheduler are running, pages and security headers, a demo copy, a guest joining with the live `GuestJoined` event over the websocket, the guest's page, and a backup. Everything it created is removed afterwards. Needs no API keys. Run it before pushing Docker changes.
